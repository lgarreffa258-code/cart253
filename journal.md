## october 27 2026
This week, working with events completely changed how I think about my programs because they finally feel interactive and alive. Before this, my code just ran on its own loop, but now it actually responds to outside input like mouse clicks, keyboard presses, or even time passing. It was really cool to see how adding events can change the whole meaning of a project and make the user feel like they are directly influencing a living system.
For my first prototype, I focused on basic user input like mouse clicks and key presses. I combined events with conditionals so that hitting specific keys would instantly change variables like background colors and object sizes. It was awesome to see how a simple click could completely disrupt the flow of the program. My second prototype was a bit more experimental, exploring time-based events. I wanted to see what happens when the program makes the user wait, or when things happen automatically after a certain amount of time passes. This was honestly the hardest part to understand because tracking time in code can get confusing, but it was really cool to create a sense of anticipation. For the final prototype, I focused on making the program feel "demanding," almost like it had its own body or personality, by requiring the user to spam a key repeatedly just to keep an element on the screen from disappearing.
I hope someone playing these prototypes feels a sense of control but also a bit of frustration depending on how the events react to them. I definitely want to develop the time based mechanics further in future projects.

## october 27 2026
This week, learning how to use functions completely changed how I think about writing code. At first, they honestly seemed like an unnecessary extra step just wrapping perfectly fine code inside a new set of curly brackets for no reason. But as I built my three prototypes, I realized that functions aren't about adding flashy new visual features. Instead, they make managing a ton of elements way easier and keep your code from looking like a messy, copy-pasted wall of text.
For my first prototype, I focused on parameters. Before this, if I wanted multiple elements with the same behavior, I had to copy and paste blocks of variables over and over. By putting that behavior into a single reusable function with parameters for things like position or speed, I could spawn a whole bunch of matching elements with just a few quick lines.
My second prototype explored return values, which was definitely the hardest part of the week for me. It took me a minute to wrap my head around how data flows out of a function. I ended up using a function to calculate and return randomized data for my program elements. Once I got it to work, I realized how cool it is for making things dynamic.
For the final prototype, I practiced refactoring. I wrote a chaotic program the "usual way" first, and then replaced the repetitive code with clean function calls. It was really satisfying it felt like cleaning a super messy bedroom. What surprised me most was how much shorter and easier to read my main program became.
Looking back, the coolest thing is realizing how functions let you scale up a project without making it impossible to manage. I definitely want to develop this further to handle more complex movement or interactive setups in future projects.
